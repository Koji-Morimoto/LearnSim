1. 4つの信号系統と主要ICの役割

Isaac Sim 6.2.0 のバックエンドは「どこに永続データがあり、どのランタイムバスを通り、誰が描画やセンサーへ読み出すか」という4つの信号系統で整理すると全体像が見通せます。バッジをクリックまたはホバーすると回路図上の対応 IC と連動します。

USD Stage（永続オーサリング系統）

pxr.Usd / omni.usd が管理する永続データ層です。アセット読込・ファイル保存・初期設定はすべてここに入ります。

既定の /physics/updateToUsd が有効な間は PhysX が毎フレーム結果を書き戻しますが、Fabric モードや RL 学習時は性能のため遮断します。 Editor UI (Property / Gizmo) は通常 USD Stage のみを参照します。

Fabric / USDRT（中央ランタイムバス）

usdrt.Usd / omni.fabric が担う CPU/GPU 対応の高速な配列型ストア（SoA）です。 FSDFabric Scene Delegate（omni.hydra.usdrt_delegate）。Kit 109 以降の既定で、すべての描画データを Fabric のみから読み取る Hydra Scene Delegate です。 が有効な Isaac Sim 6.2.0 では、描画の唯一の入力元になります。

OmniGraph も内部状態は Fabric 上で高速に実行し、必要時のみ USD Stage へ書き戻します。

Physics Engine & Tensor API（物理・制御系統）

Timeline & Kit Loop が PLAY の間だけ物理ステップが駆動します。PhysX は出力先を USD Stage・Fabric・Tensor API の3方向へリレー切替でき、Isaac Sim 6.2.0 で加わった Newton は Warp カーネルで直接 Fabric へ書き込みます。

Python / RL Script (Tensor API) は USD Stage も Fabric も経由せず物理バッファへ直通するため、SimulationContext.step(render=True) を OFF にしても動作します。

Hydra Scene Delegate → RTX（描画・センサー系統）

/app/useFabricSceneDelegate の ON/OFF で、Fabric 専用読取の FSD と USD 主体のレガシー OmniHydra を排他選択します。

Render Gate が ON なら STOP 中や PAUSE 中も Viewport は更新され続けます。Camera や RTX Lidar は RTX Renderer の出力に依存しますが、PhysX Sensors（Contact / IMU）は描画経路を通らず Physics Engine から直接読み出されます。

2. Timeline 状態別・Hydra Delegate 別の回路差分

Timeline の 3 状態（STOP / PLAY / PAUSE）で何が変わるか

Timeline は物理・ActionGraph・Replicator に対するマスタークロックです。描画回路（Hydra → RTX Renderer → Viewport）は Timeline が STOP でも Render Gate が ON なら通電したままになります。

信号経路 STOP PLAY PAUSE 補足・制御条件
Timeline → Physics Engine (stageupdate) 遮断 通電中 遮断（状態保持） STOP 遷移時に /physics/resetOnStop が ON なら初期 USD 姿勢へ復元
Physics → USD Stage / Fabric 出力 遮断 フラグ依存 遮断（最終値保持） PhysX は /physics/updateToUsd / /physics/fabricEnabled で分岐、Newton は Fabric 直結
USD Stage → Fabric 同期 通電中 Notice 許可時 通電中 FSD 時は USDRT Population による遅延バッチ同期（描画直前または SynchronizeToFabric()）
Hydra → RTX Renderer → Viewport Render Gate 依存 Render Gate 依存 Render Gate 依存 Render Gate OFF（Headless 無描画ステップ）で完全遮断
Timeline → OmniGraph (PlaybackTick) → ROS 2 Bridge 遮断 通電中 遮断 ROS 2 トピック送出や ActionGraph の物理ステップ連動は PLAY 中のみ駆動

常時ループ（CLOCK）vs 差分同期（DIRTY）vs 純粋イベント（EVENT）

USD Stage → Fabric は USD Stage が変化しない限り毎フレーム全量を読み直す仕組みではありません。FSD 有効時は USD Notice で変更パスだけ記録し、描画直前または SynchronizeToFabric() で差分のみバッチ反映します（未変更なら素通り）。ただし /physics/updateToUsd が ON のまま PLAY すると、PhysX が毎フレーム USD Stage を書き換えるため USD Notice が毎フレーム連鎖発火します。

駆動方式 発火タイミング 該当する主な信号経路
CLOCK 毎フレーム メインループ / 物理ステップごとに毎回実行 Timeline → Physics Engine、PhysX → USD Stage、PhysX / Newton → Fabric、Timeline → OmniGraph → ROS 2 Bridge、Hydra → RTX Renderer → Viewport
DIRTY 差分同期 イベントで変更ビットを記録し、同期点で差分のみ一括転送（未変更なら素通り） USD Stage → Fabric（FSD 有効時の USDRT Population）、Fabric → Hydra Scene Delegate（RtChangeTracker 差分同期）、Fabric 内部 CPU ↔ GPU ミラー
EVENT 変化時のみ 編集・操作・状態遷移の瞬間だけ 1 回発火 USD Stage → Fabric（OmniHydra 時の即時同期）、USD Stage → Physics Engine（USD Notice）、Fabric → USD Stage（手動 save_to_usd()）、STOP 時の初期 USD 復元、TimeSample 時刻変更イベント

FSD（既定）と OmniHydra（レガシー）の構造差分

/app/useFabricSceneDelegate を切り替えると、描画入力の配線トポロジーそのものが変化します（変化箇所のみ色帯で強調）。

比較軸 FSD ON（Isaac Sim 6.2.0 既定） FSD OFF（レガシー OmniHydra）
Hydra のデータ読取元 Fabric のみ（単一ソース） 主に USD Stage 直接 ＋ 一部 Fabric
USD → Fabric 同期方式 USDRT Population による遅延バッチ同期 USD 変更ごとの即時同期（最小限のみ）
Fabric Transform 属性形式 omni:fabric:localMatrix / worldMatrix レガシー _localMatrix / _worldMatrix
USD と Fabric の即時一致 同期前はズレ得る（明示同期が必要） 常に一致（ただし大量変更に弱い）
Newton 物理との互換性 必須（Warp が Fabric へ直接出力） 非推奨（omni:fabric:worldMatrix 非標準）
対応レンダリング機能（Mesh / Light / Material） フル対応 フル対応

3. 現場でよく起きる 5 つの「回路トラブル」診断

「物理は動いているはずなのに値が取れない」「画面だけ止まっている」といった典型的な詰まりは、ほぼすべてスイッチの噛み合わせによる断線またはインターロックです。ボタンを押すと該当状態を回路図へ即座に再現できます。

トラブル①：Viewport では物体が落ちるのに、Property Window や pxr.Usd の座標が変わらない

/physics/fabricEnabled が ON かつ /physics/updateToUsd が OFF のとき、PhysX の出力は Fabric → FSD → Viewport へ流れますが USD Stage には届きません。UI 上で確認するには ext."omni.kit.property.usd".enableAdapter を ON にし、Python からは USDRT または Tensor API を読むか、必要時に save_to_usd() を呼びます。

トラブル②：/physics/updateToUsd が ON なのに USD Stage が一切更新されない

GPU Dynamics 有効時に /physics/suppressReadback が ON になっていると、GPU から CPU への Readback 自体がインターロックで遮断されるため PhysX → USD Stage の書き戻しは機能しません。RL 学習で GPU Direct を使う場合は正常動作であり、描画が必要なら GPU Interop 経由で Fabric へ流します。

トラブル③：PLAY 中で物理計算は進んでいるのに、Viewport 上の物体が微動だにしない

/physics/updateToUsd と /physics/fabricEnabled が両方 OFF になると、PhysX の出力が USD Stage にも Fabric にも繋がらない「描画断線」状態になります（Tensor API の値だけは進みます）。

トラブル④：Render Gate OFF（render=False）にしたら Camera / RTX Lidar のデータが空になった

Camera・RTX Lidar・Replicator は Hydra → RTX Renderer の下流にあるため、Render Gate を切ると給電が止まります。一方、ContactSensor や IMUSensor などの PhysX Sensors は Physics Engine 直結のため Render Gate OFF でも動作します。

トラブル⑤：USD Stage を書き換えた直後に USDRT (Fabric) で読むと古い値が返る

FSD 有効時は USDRT Population が USD Stage の変更をバッファリングし、描画直前まで反映を遅延させます。Python から USD 編集直後に Fabric を読む場合は、読取前に明示的に SynchronizeToFabric() を実行して同期パルスを通す必要があります。
