API リファレンス（目次・逆引き・設定）

機能別に分割された 5 枚の完全仕様書への入口です。各ページには全クラス・全プロパティ・全メソッドの引数型・配列形状・単位・副作用・パフォーマンス区分・コード例を記載しています。

適用ステージ前提（単位規約）： 本拡張は metersPerUnit=1 のステージ専用です。ドキュメント内の長さ・距離・直動関節位置はすべて m（metersPerUnit=1 のステージ専用）、速度は m/s として扱います。

API 仕様書ページ一覧（機能別 5 分割）

1. 単体ロボット API（robot.py）

GeometricRobot・GeometricRobotComponent・GeometricJoint・GeometricLink。mimic 仕様・IsaacRobotAPI 自動 Component・batch_update()・VariantSet・debug_draw_colliders・write_target 制約を完全記載。

2. 干渉判定・Newton / PhysX API

GeometricScene・BatchedNewtonScene・GeometricCollisionPair・GeometricCollisionFilter・convex_meshes=True/False 実測差・DebugDraw 可視化・PhysX チェッカ／ContactMonitor。

3. 複数台バッチ API（robot_view.py）

GeometricRobotView の GPU バッチ FK・一括干渉・一括クリアランス・CUDA Graph・use_gpu_fabric_writer の前提と制約。

4. モデル・生成元・IK・コマンド変換 API

GeometricRobotModel（independent_dof_indices・mimic_matrix 等全項目）・UsdArticulationSource・DH/MDH/Screw/URDF・KinematicChain / IKSolver・CommandConverter。

5. Sublayer・Writer・座標変換 API

GeometricLayer・LocalPoseSolver・GeometricUsdWriter / FabricWriter / GpuFabricWriter・transforms.py 全関数。

パフォーマンス指針（最速ホットパス vs 低頻度便利パス）

性能が最優先事項であるための使い分け原則：
毎フレーム（60+ FPS）呼ぶ制御・軌道計画ループでは「ホットパス可」「高速・事前バインド」の API だけを使ってください。名前解決（辞書・dof_names=）や USD 書き出し（flush_to_usd()）・DebugDraw は初期化・テスト・デバッグ用途に限定することで最大性能を維持できます。
やりたいこと毎フレーム最速の書き方初期化・デバッグ用の書き方参照ページ
全軸を更新するrobot.set_dof_positions(np_arr)robot.set_dof_positions({"j1": 10.0, ...})robot_api.html
マルチアームの 1 本だけ更新事前取得 arm0 = robot.get_component("arm0") → arm0.set_dof_positions(arr)arm0.set_dof_positions({"arm0_s1": 10.0})robot_api.html
複数アームを同時更新with robot.batch_update(): arm0.set_dof_positions(q0); arm1.set_dof_positions(q1)（FK 1 回）robot.set_dof_positions(dict_all)robot_api.html
独立軸（mimic 除く）だけ扱う初期化時に indep = robot.independent_dof_indices → set_dof_positions(q, dof_indices=indep)robot.get_dof_positions_dict(independent_only=True)robot_api.html

トップレベルから import できる名前一覧

from myext.robot.geometric_newton import ... で直接取り込めるシンボルは、__init__.py の __all__ に列挙された 2 グループです。USD / Kit / Newton 側のシンボル（_LAZY）は初めて参照された時点で遅延 import されるため、Isaac Sim / Kit を起動しない通常の Python + NumPy 環境でも Pure NumPy 層の名前をそのまま使えます（拡張ルートディレクトリ＝myext/ を含むフォルダを sys.path に追加するだけ）。

主な例外一覧

例外クラス主な発生条件
ValueError引数の値・配列形状が不正、指定 Prim が存在しない、剛体をつなぐ Joint が見つからない、可動範囲外で limit_policy="error"、異なる GeometricLayer や異構造ロボットを GeometricRobotView へ混在させた、同一 DOF へ 2 箇所から書き込む apply_command、など。
KeyError存在しない DOF 名・リンク名・関節名・コンポーネント名・IK ソルバー名・未登録の障害物パス（set_obstacle_pose）を指定した。
NotImplementedError未対応の USD Joint に遭遇して unsupported_joints="error" のとき、または逆変換できない GeometricCommandConverter で from_dof_positions() / read_command() を呼んだとき。
RuntimeErrorパラメータ生成ロボット（from_dh 等）で VariantSet 系 API を呼んだ、閉じた（close() 済みの）GeometricScene を使った、collision_mode="kinematic" で Stop 中に PhysX チェックを呼んだ、など。
FileNotFoundErrorattach_collider_layer() 等で指定した外部コライダーレイヤーが開けない。
GeometricStructureChangedErrorset_variant() / rebuild() による構造再構築の前に生成した KinematicChain / IKSolver / GeometricRobotView をそのまま使用した（RuntimeError サブクラス）。
