GeometricRobot / GeometricRobotComponent API

単体ロボット・複合ロボットの生成、関節操作、Mimic 規約、batch_update、VariantSet、干渉判定、DebugDraw 可視化、IsaacRobotAPI コンポーネント操作の完全仕様（metersPerUnit=1 のステージ専用）。

GeometricRobot 生成・ファクトリ

GeometricRobot は、物理ソルバーを介さずに順運動学（FK）で全リンクのワールド姿勢を計算し、Fabric または USD Sublayer へ直接書き込む単体ロボット API です。通常の利用では GeometricRobot.from_articulation(...) などのクラスメソッドから生成します。長さ・距離・直動関節位置の単位はすべて m（metersPerUnit=1 のステージ専用） です。

構造・DOF・Mimic プロパティ

Mimic 従属 DOF の重要仕様（Isaac Sim ArticulationRootAPI 互換）： robot.dof_names と robot.num_dofs には Mimic 従属関節も含まれます（PhysX Articulation と同じ配列長・順序）。ただし set_dof_positions() 実行時に model.resolve_mimic() が必ず適用されるため、Mimic 従属 DOF のスロットへ渡した値は親 DOF の式 q_dep = multiplier * q_ref + offset で必ず上書きされます。独立に指令すべき軸だけを得るには independent_dof_indices / independent_dof_names を使用してください。

namestrロボット名（model.name）。
stage / model / layer / info各内部オブジェクト操作対象 Stage・純粋運動学モデル・幾何 Sublayer・読込時メタ情報（UsdRobotInfo | None）。

副作用・前提・落とし穴1) 性能の使い分け：高頻度ループでは idx = robot.get_dof_indices(...) をループ外でキャッシュし、配列＋dof_indices=idx（または component.set_dof_positions(arr)）を使うこと。辞書や dof_names は毎回 Python 辞書探索が入る。
2) Mimic 上書き：Mimic 従属 DOF に値を渡しても resolve_mimic() で親 DOF から再計算される。
3) batch_update() 中：内部配列 _q だけ更新し、FK と書込は with ブロック脱出時に 1 回だけ実行される。

GeometricRobot.batch_updateホットパス最適化（FK 1 回化）
with robot.batch_update(): ...

コンテキスト内の複数回にわたる set_dof_positions() / component.set_dof_positions() / set_world_poses() の FK 計算・Mimic 解決・Fabric 書込を保留し、ブロック終了時に 1 回だけ実行します。

戻り値 / 型コンテキストマネージャ（ネスト対応：最外のブロック終了時のみ実行）。
副作用・前提・落とし穴効果：例えば 4 本アーム＋ベース（5 コンポーネント）を個別に更新する場合、通常は FK と Fabric 書込が 5 回走るが、with robot.batch_update(): で囲むと FK 1 回＋Fabric 書込 1 回に集約される。ブロック内で例外が発生した場合は保留分をフラッシュせず抜ける。
arm_a = robot.components["arm_a"] arm_b = robot.components["arm_b"] with robot.batch_update(): arm_a.set_dof_positions(q_a) # _q への代入のみ arm_b.set_dof_positions(q_b) # _q への代入のみ # ここで FK 1 回 + Mimic 解決 1 回 + Fabric 書込 1 回が実行される

GeometricRobotComponent

GeometricRobotComponent は、1 台の複合ロボット（例：multi_arm のベース＋4 本のアーム＋各グリッパー）のうち 特定部位のリンク群と DOF 群だけを切り出して扱う軽量ハンドルです。独自の配列や FK を重複保持せず、内部では親 GeometricRobot の dof_indices スライスへ直接委譲するため、ホットループでの追加コストはほぼゼロです。

副作用・前提・落とし穴1) 番号系の違いに注意：comp.dof_indices は親 robot 内の DOF 番号だが、comp.independent_dof_indices はこのコンポーネント内のローカル番号（0 .. comp.num_dofs - 1）であり、comp.set_dof_positions(q_ind, dof_indices=comp.independent_dof_indices) へそのまま渡せる。

3) 複数部位の同時更新：with robot.batch_update(): で囲むことで FK を 1 回に集約できる。
# multi_arm (54 DOF) でも、左アーム (6 DOF) だけを 6 要素配列で操作 left = robot.components["left_arm"] right = robot.components["right_arm"] with robot.batch_update(): left.set_dof_positions([0.0, -1.2, 1.5, -1.8, -1.57, 0.0]) right.set_dof_positions([0.0, -1.2, 1.5, -1.8, -1.57, 0.0]) # 左アーム配下の VariantSet だけを切り替え left.set_variant("Gripper", "Robotiq_2F_85")
