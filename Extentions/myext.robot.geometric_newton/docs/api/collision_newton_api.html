干渉判定・Newton / PhysX API

GeometricScene・BatchedNewtonScene の完全仕様、convex_meshes=True/False の実測差と水密メッシュ要件、GeometricCollisionPair・GeometricCollisionFilter・PhysX バックエンド（metersPerUnit=1 のステージ専用）。

GeometricScene・resolve_newton_device

GeometricScene は、Newton 1.6.1 の ModelBuilder と CollisionPipeline をラップした自前コリジョン空間です。PhysX の PhysicsScene に依存しないため、write_target="fabric" かつ Play=OFF（停止状態）でも 0 フレーム遅延で自己干渉・環境干渉・ロボット間干渉・符号付き距離を計算できます（距離・座標はすべて m、metersPerUnit=1 のステージ専用）。

Newton / Warp の実行デバイス文字列を解決します。"auto" 指定時は CUDA デバイスが利用可能なら "cuda:0"、不可なら "cpu" を返します。

戻り値 / 型解決済みデバイス文字列（例: "cuda:0" または "cpu"）。

convex_meshes=True vs False 実測仕様

USD の UsdGeom.Mesh（STL / CAD インポート由来のコライダー等）を Newton へ登録するとき、convex_meshes フラグが形状変換と Narrow Phase アルゴリズムを決定します。プリミティブ形状（Cube / Sphere / Capsule / Cylinder / Cone）はこのフラグの影響を受けず常に解析形状のまま登録されます。

比較項目convex_meshes=True（既定）convex_meshes=False
Newton 内部登録型GeoType.CONVEX_MESH（add_shape_convex_hull）GeoType.MESH（add_shape_mesh、三角メッシュそのまま）
凹部・溝・穴の扱い外殻を包む単一凸包になるため、溝や穴の空間も「中身あり」として衝突する三角メッシュの凹み・溝・穴の空間を正確にすり抜け判定できる
Newton 1.6.1 狭域判定実装GJK / MPR / SAT 凸体アルゴリズムBVH 加速三角メッシュ対メッシュ（sdf_contact.py / mesh_query_point_sign）
U 字水密メッシュ実測：溝に非接触挿入（真値 0 件）誤検知 1 件（separation = -0.2500 m）0 件（正確）（separation = None）
U 字水密メッシュ実測：5 cm 貫通（真値 −0.0500 m）過大評価（separation = -0.4500 m）1 件（separation = -0.050000004 m、誤差 4 nm）
RTX 3060 処理時間（28 三角形ペア）2.351 ms / call2.391 ms / call
必須メッシュ品質条件頂点集合から凸包を生成するため穴あきメッシュでも破綻しにくい閉じた水密（watertight）多様体メッシュで、内部に重複する共面（coplanar internal faces）が無いこと
convex_meshes=False 使用時の厳守事項（水密性）： 実機検証で確認した通り、複数ボックスの単純結合のように「内部に閉じた境界の共面が残る非水密メッシュ」や「法線反転・穴開きメッシュ」を GeoType.MESH に渡すと、mesh_query_point_sign の内外符号が反転して非接触でも誤検知が発生します。凹形状を精密判定したい場合は、CAD / Blender 等で boolean 結合・法線統一した水密 STL / USD メッシュを用意してください。

GeometricScene 同期・環境モード・判定・DebugDraw

環境障害物の 2 モードと手動姿勢上書きのルール：
1) 自動検出モード vs 明示登録モード：add_environment() を 1 回も呼んでいない状態では自動検出モード（/World、なければ / 配下のロボット外 CollisionAPI 付き Gprim を全検出）。add_environment() を 1 回でも呼ぶと明示登録モードへ切り替わり、渡したルート配下だけを対象にする。clear_environment() を呼ぶと自動検出モードに戻る。
2) 自動同期と set_obstacle_pose()：robot.check_collisions() / compute_clearances() は環境を含む scope 時に毎回 sync_environment(reset_manual_overrides=False) を自動実行するため、USD で動かした障害物は自動追従する。一方 set_obstacle_pose() で置いた障害物には手動上書きフラグが付き自動同期では上書きされない。USD / Fabric 側へ戻すには sync_environment()（既定 reset_manual_overrides=True）を明示的に呼ぶ。未登録パスを渡すと KeyError。
3) close() 後の利用：close() 済みの GeometricScene を使用すると RuntimeError。

BatchedNewtonScene

BatchedNewtonSceneN 台同時 GPU バッチ（CUDA Graph 対応）
BatchedNewtonScene( view: GeometricRobotView, *, device: str = "auto", environment_roots: Sequence[str] | None = None, broad_phase: Literal["auto", "explicit", "nxn", "sap"] = "auto", convex_meshes: bool = True, bake_adjacent_filter: bool = True, bake_collision_filter: bool = True, use_cuda_graph: bool = True, )

GeometricRobotView（同一構造のロボット N 台）のために、N 台分の FK と衝突判定を 1 回の GPU カーネル起動（CUDA Graph キャプチャ対応）で並列実行するバックエンドクラスです。通常は GeometricRobotView 経由で利用します。

引数 / フィールド型既定値意味・形状・単位・制約
viewGeometricRobotView必須対象となる同一構造ロボットのビュー（台数 N）。
devicestr"auto"Warp/Newton 実行デバイス（CUDA 利用可なら "cuda:0"）。
environment_rootsSequence[str] | NoneNone全ロボット共通の障害物（Newton の world=-1）としてまとめて登録するルート Prim パス列（ロボットごとの個別環境ではない）。None のとき /World（なければ /）を自動探索。
broad_phase"auto" | "explicit" | "nxn" | "sap""auto"Broad Phase アルゴリズム選択。"auto" は全ワールド合計 16,384 形状以下で "explicit"、16,385 以上で "sap" を自動選択します。
convex_meshesboolTrueUsdGeom.Mesh を単一 Convex Hull 化するか（True）、生三角メッシュにするか（False）。

戻り値 / 型プロパティ: device, newton_model, newton_state, prim_body_indices。
主要メソッド: eval_fk_batch(q_batch, base_batch, *, resolve_mimic=True, return_matrices=True)（q_batch は (N, D)、base_batch は (N, 4, 4)）、sync_environment(*, use_fabric='auto')、check_collisions_batch(...)、compute_clearances_batch(...)、close()。
副作用・前提・落とし穴ロボット間干渉は判定しない：各ロボットは独立ワールド 0..N-1 へ配置されるため、自ロボット内のリンク同士および全ロボット共通障害物（world=-1）との干渉のみを並列判定する。

PhysX バックエンド（GeometricCollisionChecker / GeometricContactMonitor）

PhysX バックエンドの動作条件と制約： 既定の collision_mode="none" では PhysX コライダーを完全に無効化しているため、collision_backend="physx"（または GeometricCollisionChecker）を呼ぶと RuntimeError になります。PhysX バックエンドを使う場合は GeometricLayerOptions(collision_mode="static")（または "kinematic"）を指定してください。collision_mode="static" であれば GeometricCollisionChecker._prepare() が判定直前に robot.flush_to_usd() を自動で呼ぶため、write_target="fabric" のまま Stop 中でも Play=ON 中でも動作します。一方 collision_mode="kinematic" で Stop 中に判定を呼ぶと RuntimeError になります。なお PhysX overlap_shape は 1 フレーム遅延・入力メッシュ凸包近似・距離 separation=None となるため、通常は既定の collision_backend="newton" を推奨します。
