内部の 2 層構造、数値規約、なぜ非公式の幾何＋Newton 経路をこう設計しているのか（Why）、公式ドキュメント・同梱ソース出典を自己完結で解説します。

1. モジュール依存関係（2 層アーキテクチャ）

myext.robot.geometric_newton は、Isaac Sim に一切依存しない Pure Python + NumPy 層（model/） と、OpenUSD・Fabric・Newton・PhysX に接続する 統合層（トップレベル） の 2 層で構成されています。__init__.py は model/ 配下を即時公開し、USD / Kit / Newton 依存クラスは __getattr__ で遅延 import しています。

モジュール 2 層構造図（ホバー／クリックで連動） 色＋番号バッジで対応先を強調

1model/ が数学・運動学の正本を担い、 2usd_reader.py・layer.py・writer.py が USD/Fabric 境界を吸収し、 3newton_backend.py が 0F 遅延衝突と DebugDraw を実行し、 4GeometricRobot / GeometricRobotView が利用者の入口に全設定を露出します。

2. エンドツーエンドのデータフロー（set_dof_positions → 描画＆0F 干渉）

1 回の姿勢更新と干渉判定のデータフロー

1resolve_mimic(q) で従動軸を確定後、 2fk_backend で全リンク姿勢を算出し、 3write_target へ描画出力する経路と、 4collision_backend で 0F 干渉判定する経路が並列に分岐します。

4. 主要な設計判断の理由（Why）

4.1 なぜ builder.add_usd() ではなく GeometricRobotModel から Newton を組むのか

  1. GeometricLayer との衝突回避：Sublayer で articulationEnabled=false / jointEnabled=false を書いているため、builder.add_usd() では全リンクが 6 自由度浮遊剛体または Orphan joints エラーになる。
  2. 逆向き Joint（body1 が親）への完全対応：usd_reader.py で正規化済みの木を使うことで例外を回避。
  3. 非 USD ソースへの統一対応：DH / MDH / Screw / URDF / attach() には USD Joint がないが同一パイプラインで動作。
  4. 任意 dof_order と Variant 再構築：dof_to_newton_q 置換テーブルだけで整合を維持。

4.2 なぜ VariantSet 切替時だけ USD（Sublayer）へ 1 回書き戻すのか

公式 Doc（fsd_vs_omnihydra.md）の通り、Fabric は合成後（post-composition）キャッシュであり、VariantSet のような合成前変更は USD Stage（Session Layer）に書く必要があります。Variant 切替時に USD Resync が走ると、USDRT Population が次の描画直前に USD の Transform で Fabric を上書きするため、書き戻さないと 1 フレーム初期位置へ戻るちらつきが起きます。そのため _rebuild() 時だけ現在姿勢を Sublayer へ 1 回書き戻し、さらに 3 フレーム間 _repush_frames で Fabric へ再送しています（通常フレームでは USD 非書込）。

4.3 なぜ convex_meshes=True（既定）と False（生三角形メッシュ）を切り替えられるのか

convex_meshes=True はすべての UsdGeom.Mesh を compute_convex_hull() で単一凸包（GeoType.CONVEX_MESH）へ変換し、GJK/MPR で高速判定します（凹みの溝は埋まる）。convex_meshes=False は STL 等の元の三角形メッシュ（GeoType.MESH）をそのまま登録します。実機（RTX 3060）で水密 U 字メッシュ対を計測した結果、True では溝の中を誤検知（5 cm 貫通時も −0.45 m）したのに対し、False では溝の中を非接触（0 件）、5 cm 貫通時 −0.0500 m と厳密一致しました。ただし生メッシュ同士の符号判定（mesh_query_point_sign）は 閉じた水密メッシュ（内部の重複面なし） を前提とし、高ポリゴン STL 同士では計算時間が増えます。

4.4 なぜ Show by Type > Physics > Colliders のピンク表示が Fabric 駆動で動かないのか

write_target="fabric"（既定）は高速化のため USD の xformOp を書き換えません。一方、Isaac Sim の Show by Type > Physics > Colliders（omni.physx.ui）は同梱公式 Doc（collision_debug_vis.rst）の通り UsdPhysics のコライダー表示であり、Static Collider（ピンク）は USD 側の初期姿勢に留まります。そのためデバッグ時に Newton 内部の実形状を 0F 遅延で確認できるよう、USD へ書き戻さない debug_draw_colliders=True（通常＝シアン、干渉中＝赤、接触点・めり込み線分＝オレンジ）を用意しています（OFF 時は負荷ゼロ）。

4.5 なぜ IsaacRobotAPI から GeometricRobotComponent を自動生成するのか

54 DOF のマルチアームロボットを 1 本の配列インデックスで管理すると、軸対応の把握や Variant 切替時の番号ズレが破綻します。Isaac Sim の IsaacRobotAPI（RobotSchema.usda）にはサブロボット構成と isaac:physics:robotLinks が定義されているため、auto_components=True（既定）で初期化時に各サブロボットの GeometricRobotComponent を自動生成し、内部の NumPy 整数配列 dof_indices をキャッシュすることで 書きやすさと最速ホットパスを両立 しています。

4.6 builder.rigid_gap=0.0・sync_environment(use_fabric="auto")・GPU Fabric・GeometricLayer

  • rigid_gap = 0.0 と実行時 shape_gap 切替：Newton 既定 0.1 m を 0 へ落とし、クリアランス計測時のみ 0.5 * d + 1e-4 へ書き換えて再構築なしで任意距離を計測します。干渉とクリアランス両方が必要なら compute_clearances() 1 回で両方分類する方が約 2 倍高速です。
  • sync_environment(use_fabric="auto")：Play 中の動的剛体障害物は Fabric、静的障害物と Stop 中は USD XformCache から自動読み分けます。
  • GeometricGpuFabricWriter：毎フレーム SelectPrims をフレッシュ取得し、タグ付け時に omni:fabric:localMatrix を除去して IFabricHierarchy の上書きを防ぎ、末尾で wp.synchronize_device() で描画競合を防ぎます。
  • GeometricLayer：Session Layer 先頭の匿名 Sublayer に 5 属性のみ上書きするため、元 USD を一切汚染せず layer.remove() で完全復帰します。
