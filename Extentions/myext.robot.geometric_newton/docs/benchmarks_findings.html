実測ベンチマーク・Red → Green 検証知見

Isaac Sim 6.2.0 実機で Red（問題・劣化の再現）と Green（対策後の改善）を計測した結果を、大小比較・時間内訳・フレーム推移が直感的に読み取れるインライン SVG グラフでまとめています。

検証環境と主要サマリー

すべての実測値は Windows 11 Pro / Intel Core i7-13700K / NVIDIA GeForce RTX 3060 (12 GiB) / Isaac Sim 6.2.0 / Newton 1.6.1 / Warp 1.17.0 の実機で取得しています。各検証は切替フラグ 1 行だけが異なる *_Red.py と *_Green.py のペアとして tests_red_green/ に保存してあり、WinMerge で差分を確認しながらいつでも再実行できます。

01. USD 書込直後の Fabric 1 フレーム戻り（ちらつき）防止

_usd_sync_pending の追加により、frame +1 に残っていた 1.32 m のちらつきを全フレーム 0.000 m へ解消 折れ線グラフ（フレーム推移） / UR10e Case A: flush_to_usd() 直後に Fabric 移動

1ガードを無効にした Red: ガード無効 は USD→Fabric 同期により旧姿勢へ戻ったまま固着します（Case B set_variant は 1.323 m、Case C layer.apply は 1.478 m）。 2実測により 修正前 (_repush のみ) では frame +1 に 1 フレームのちらつきが残っていたことが判明しました。 3_usd_sync_pending を導入した Green: 修正後（既定） では、定常フレームの USD 非書込を維持したまま全フレームで誤差 0.000 m を達成しています。

02. Newton Broad Phase への collision_filter 事前登録（時間内訳と接触数）

Broad Phase 登録により Narrow Phase の無駄な接触計算（0.521 ms / 42 接触）を 100% 削減 積み上げ横棒グラフ（時間配分）＋接触数バー / UR10e + Robotiq_2F_85（200 反復平均）
なぜ単体 1 台では約 20% 短縮にとどまり、バッチや凹メッシュで桁違いに効くのか： 時間配分バーが示す通り、単体 1 台・単純凸包では固定費（Fabric 書込と CUDA 起動／CPU-GPU 同期の 2.188 ms）が大半を占めるため、Narrow Phase の無駄計算（0.521 ms）を丸ごと消した効果が全体の 19.2% に見えます。一方、convex_meshes=False の高密度凹メッシュや BatchedNewtonScene（例: 1024 台並列）では固定費が薄まり、未登録では 42 接触 × 1024 台 ＝ 43,008 件/step の無駄接触が Narrow Phase と接触バッファを圧迫するため、Broad Phase 除外が不可欠になります。

03. Session Sublayer の collision_mode="none" vs "static"

collision_mode="none" で PhysX のロボットコライダーを 7 → 0 個へ削減しつつ、Newton 検知は完全維持 ペア横棒グラフ / UR10e（instanceable collisions を含む）＋環境障害物 /World/Obs

04. 毎フレーム書込先 write_target="usd" vs "fabric"（時間配分）

write_target="fabric" は set_dof_positions() を 2.23 倍高速化し、USD 書込回数を 120 → 0 回へ削減 積み上げ横棒グラフ（1 フレーム時間配分） / UR10e + Robotiq_2F_85（120 フレーム平均）

05. 54 DOF 4 アームロボットの書き込み方式別速度比較

with robot.batch_update(): なら部位別でも一括配列と +0.067 ms 差、付け忘れは 5.13 倍悪化 ソート済み横棒グラフ（0 基準＋ベースライン破線） / multi_arm 54 DOF・59 リンク（300 反復平均）
設計上の結論： 並列 4 アームではロボット全体の dof_names が幅優先（階層順）で入り組みますが、with robot.batch_update(): の中で GeometricRobotComponent または GeometricDofBinder を使えば、一括配列との差は 60 fps 予算（16.67 ms）の 0.4% 未満（+0.055〜0.067 ms）に収まります。ダミー軸（lower==upper）でモデルや IK を汚す必要はありません。

06. VariantSet 再構築の時間内訳と U 字凹メッシュ精度

54 DOF ロボットの VariantSet 再構築（計 22.23 ms）は USD 読取（53%）と初期姿勢書込（33%）が大半 積み上げ横棒グラフ（Kit 実測 last_rebuild_timings）＋ 凹メッシュ精度比較
