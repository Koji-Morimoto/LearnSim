# 検証結果：物理シーンを「疑似的な幾何シミュレーション」に切り替えて戻す

実施日：2026-11-02
対象：Isaac Sim 6.2.0（GUI アプリ内で実行、物理エンジン PhysX、`/physics/updateToUsd = True`、Fabric 拡張は無効）

## 1. 結論

- **幾何モード**＝「物体は位置を書いた所にだけ動き、PhysX は干渉（接触）の検出だけを行う」状態は、次の 4 つで作れる。
  1. 重力を 0 にする
  2. 全剛体を kinematic にする（`physics:kinematicEnabled = true`）
  3. 剛体に ContactReportAPI を付ける（threshold 0）
  4. PhysicsScene の `reportKinematicKinematicPairs` と `reportKinematicStaticPairs` を true にする
     → **これが無いと、通り抜けても接触が 1 件も報告されない**（P3）
- **元に戻せる仕組み**：上書き値はすべて専用の匿名レイヤーに書き、そのレイヤーをセッションレイヤーの下に差し込む。戻すときはそのレイヤーを外すだけ。元の設定（Root Layer）は一度も書き換えない。
  - 戻した後の合成結果は元と**差分 0**。Root Layer の `/World` 以下の文字列も**完全一致**（P5）。
  - 幾何モードのまま保存しても、ファイルに幾何モードの値は入らない（P4）。
- **重要な制約**：**止まっている物体同士の干渉は報告されない**。最初からめり込んでいても、どちらかが動かない限り接触レポートは来ない（Q2）。

## 2. 幾何モードで不要になる設定・まだ必要な設定

### 不要になる（効かなくなる）設定

| 区分 | 設定 | 根拠 |
|---|---|---|
| シーン | 重力（0 にする） | P2 で浮いた球が落ちない |
| シーン | ソルバ種別（TGS/PGS）、反復回数、stabilization、bounce threshold、摩擦の相関距離など | 力学を解かないので効く場面が無い（推論。個別には測っていない） |
| 剛体 | 質量・慣性・重心（MassAPI）、初速度 | P2 で全物体の移動量 0（初速度付きの球も動かない） |
| 剛体 | 減衰・速度上限・sleep 閾値・最大めり込み解消速度・反復回数（PhysxRigidBodyAPI） | 推論（kinematic は積分されない） |
| 剛体 | CCD | kinematic には効かない。幾何モードでは明示的に切る |
| マテリアル | 摩擦・反発係数 | P2 で Target が押されない（応答が無い） |
| ジョイント | ドライブ（剛性・減衰・最大力）、ジョイント摩擦、可動範囲 | P2 で腕が垂れない。幾何モードではジョイント自体を無効化 |
| アーティキュレーション | アーティキュレーション全体 | 無効化してリンクを個別の kinematic 剛体として扱う |

### まだ必要な（干渉の判定に効く）設定

| 設定 | 理由 |
|---|---|
| コリジョン形状と近似方法（convex hull / SDF / 三角メッシュ） | 何を「干渉」とみなすかを決める |
| `contactOffset` / `restOffset` | **触れる前から接触が報告される**。実測で 1.67 cm 手前（separation = +0.0167）から来た。干渉かどうかは separation ≤ 0 で判定する |
| CollisionGroup / FilteredPairs | 干渉を調べない組み合わせの指定は、そのまま効く |
| 物理のステップ数（Hz） | 検出の時間刻みになる。1 m/s・60 Hz では 1 ステップ 1.67 cm 進む。Wall は 1.7 cm めり込んだ状態で初めて検出された |
| ContactReportAPI・kinematic 組の報告フラグ | 無いと検出されない（P3） |

## 3. 仕組み

```text
Session Layer
  └─ 幾何レイヤー(匿名, customLayerData geometricMode=true) ← 上書きはここにだけ書く
Root Layer (geometric_mode_demo.usda)                     ← 元の設定。編集先はこのまま
```

- 強いレイヤーの値が勝つので、Root の `gravityMagnitude = 9.81` は残ったまま、見かけ上 0 になる。
- 幾何モード中にユーザーが GUI で値を変えると、編集先は Root のままなので Root に書かれる。ただし幾何レイヤーが勝つため、画面上は変わらない（P4：重力を 5 にしても合成値は 0、戻すと 5）。
- 物体を動かす書き込みも `geometric_mode.edit_context(stage)` の中で行えば幾何レイヤーに入り、戻すときに一緒に消える。デモのドライバ（Mover の移動と、接触イベントの種類による色分け）はこの方法を使っている。

```python
import geometric_mode as gm
gm.enable(stage)                      # 幾何モード
with gm.edit_context(stage):          # 幾何モード中だけの書き込み
    op.Set(Gf.Vec3d(x, 0, 0.6))       # kinematic 剛体の xform を書くと、PhysX がその位置へ動かす
gm.disable(stage)                     # 元に戻す
```

## 5. 注意点

1. **止まっている物体同士の干渉は検出されない。** 「この姿勢で干渉しているか」を 1 回だけ調べたい用途には、接触レポートではなくシーンクエリ（`overlap_*`）を使う（[physx_overlap_contact_verification](../physx_overlap_contact_verification/検証結果_LN-PhysX干渉検出API比較.md) を参照）。
2. **接触レポートは触れる前から来る**（contactOffset の範囲）。干渉の判定は separation ≤ 0 で行う。
3. **ステップ間の移動量が物体の厚みを超えると、すり抜けて見逃す可能性がある**（今回は未検証。1 ステップ 1.67 cm で厚さ 10 cm の Wall は検出できた）。
4. 切り替えは Stop 中に行う（`enable` / `disable` は Play 中なら自動で Stop する）。物理の設定は Play 開始時に読まれる。
5. 変形体・粒子は対象外（見つけたら警告を出すだけ）。
6. アーティキュレーションは無効化するので、関節角を指定して動かす場合は各リンクの位置を自分で計算して書く必要がある（理由は §6）。

## 6. 追加検証：アーティキュレーションは無効化しないとだめか（v04）

Link の通り道（45°）に kinematic の障害物を置き、関節角を 0° → 90° → 0° に振った。[results/v04_articulation.json](results/v04_articulation.json)

| ケース | 設定 | 動かし方 | 角度の誤差（最大） | 障害物との接触 |
|---|---|---|---|---|
| A | アーティキュレーション有効 + リンク kinematic | 関節角を直接書く | **動かせない** | なし |
| B | アーティキュレーション有効 + リンク dynamic（重力 0） | 関節角を毎フレーム直接書く | 6.06°（接触中だけ押し戻される） | 検出（フラグ不要） |
| B2 | 同上 | 硬い位置ドライブの目標角 | 62.9°（27.1° で障害物に止められる） | 検出 |
| C | アーティキュレーション無効 + リンク kinematic（現行） | 順運動学で xform を直接書く | **0.00°** | 検出 |

- A：PhysX が `cannot create a joint between static bodies` を出してジョイントを作らず、アーティキュレーション自体ができない（kinematic はジョイントの相手として static 扱い）。テンソル API も `did not match any articulations` で使えない。
- B：関節角で動かせて干渉も取れるが、接触中は PhysX の押し戻しが入り、読み返した姿勢が指令からずれる（30° 指令 → 27.1°、60° → 62.9°）。障害物の側は動かない。
- C：指令どおりに動くが、関節角 → リンク姿勢の変換（順運動学）を自分で書く必要がある。

**C で見つけた不具合と修正**：ジョイントを無効化すると、ジョイントが持っていた「繋がった 2 物体は衝突しない」除外も消え、Base–Link が常に接触として報告された（181 件）。`geometric_mode.enable` で、`physics:collisionEnabled = false` のジョイントの両端に `FilteredPairsAPI` を幾何レイヤーへ書くようにした。修正後は Base–Link の報告 0 件。

## 7. 補足：コライダーの線の色（v05）

ビューポートのコライダー表示（`/persistent/physics/visualizationDisplayColliders = 2`、Show By Type > Physics > Colliders の All）は、剛体の種類で色が変わる。Target だけ kinematic にすると Target だけ黄色になった（[物理](results/color_1_physics.png) / [幾何](results/color_2_geometric.png) / [Target だけ kinematic](results/color_3_mixed.png)）。

| 線の色 | 種類 |
|---|---|
| 緑 | dynamic 剛体 |
| 黄 | kinematic 剛体 |
| マゼンタ | 静的コライダー（RigidBodyAPI なし） |

色を決めるコードは C++ プラグイン内にあり、ドキュメントの記載は見つからなかった。上の対応は撮影結果から判断した。

## 8. 補足：接触イベントの種類で色分け（v06）

デモのドライバ（[code/geo_demo.py](code/geo_demo.py) の `Driver`）は、接触レポートの種類ごとに色を変える。FOUND と LOST は 1 回しか来ないので、タイムライン時刻で一定時間だけ色を残す（一時停止中は色が残ったまま）。

| イベント | 色 | 表示の長さ | 1 回の通り抜けで来た数（Mover–Target / Mover–Wall） |
|---|---|---|---|
| `CONTACT_FOUND` | 赤 | 0.3 秒（`FOUND_HOLD`） | 1 / 1 |
| `CONTACT_PERSIST` | 紫 | 接触が続く間 | 約 62 / 36（物理の 1 ステップごとに 1 回） |
| `CONTACT_LOST` | 青 | 0.6 秒（`LOST_HOLD`） | 1 / 1 |

- 1 つのコライダーが複数の組で同時に接触しているときは、FOUND ＞ PERSIST ＞ LOST の順で優先する。
- 色は幾何レイヤーに書くので、幾何モードを外すと元の色に戻る。
- 最初は PERSIST を橙にしたが、描画すると黄色に見えて kinematic の黄色い線・黄色い箱と紛れたため、紫に変えた。
- 6 つの時点で一時停止し、内部の状態と実際の displayColor が一致することを確認した（[results/v06_event_colors.json](results/v06_event_colors.json)、[画像](results/event_grid.png)：上段 Target の FOUND→PERSIST→LOST、下段 Wall の FOUND→PERSIST→LOST）。
- 往復で FOUND が出た時刻は Mover–Target で 2.0 秒と 8.0 秒、LOST は 3.05 秒と 9.05 秒。
