# バックエンド選択の仕組み

Core Experimental API が、どの条件でどのバックエンドを選ぶかを、v6.2.0 のソースと実測（2026-11-09）でまとめたノートである。

## このノートで使う用語

| 用語 | 意味 |
|---|---|
| 状態 | timeline の状態。Stop / Play / Pause の3つがある |
| バックエンド | Core Experimental API がデータを読み書きする経路。usd / usdrt / fabric / tensor / simstate がある |
| 物理エンジン | 力・拘束・接触を解いて次の状態を計算する本体。PhysX / Newton がある |
| ラッパー | Core Experimental API の `isaacsim.core.experimental.prims.Articulation`・`isaacsim.core.experimental.prims.RigidPrim`・`isaacsim.core.experimental.prims.XformPrim` などのクラス。1つのラッパーが1個以上のプリムを受け持つ |
| 姿勢 | 位置と向きの組。スケールは含まない |
| view | `omni.physics.tensors` が提供するオブジェクトで、実行中の物理エンジンの内部オブジェクト群をまとめて読み書きする窓口 |
| simulation view | ステージと物理エンジンの組ごとに1つ作られる view の入口。Play で作られ、Stop で無効になる |
| 子の view | simulation view から、プリムのパスを指定して作る view。ラッパーは tensor で読み書きするためにこれを内部に持つ |
| 候補リスト | メソッドが `isaacsim.core.experimental.utils.backend.get_current_backend()` に渡す、対応するバックエンドを優先順に並べたリスト |
| 指定値 | `isaacsim.core.experimental.utils.backend.use_backend()` の with ブロックの中で有効な、利用者が指定したバックエンド。`isaacsim.core.experimental.utils.impl.backend._context.backend` に入っている |
| tensor 専用のメソッド | 候補リストを持たず、tensor でしか処理しないメソッド |
| フォールバック | 選ばれたバックエンドが使えないために、別のバックエンドに差し替わること |
| strict | `isaacsim.core.experimental.utils.backend.use_backend()` の2つのフラグ（raise_on_unsupported と raise_on_fallback）を True に固定したもの。指定どおりに処理されなければ例外になる |
| スパイ | 元の関数を包み替えて、呼ばれるたびに中身を表示させる観測用のコード |
| 物理の出力先 | 物理エンジンが計算した姿勢を、毎ステップどこへ書き出すか。USD・Fabric・どちらにも書かない、の3通りがある |

ほかの用語の定義は [用語集](../01_用語と概念/01_用語集.md) にまとめている。

## 一言要約

- Core Experimental API のメソッドは、3段階の判定でバックエンドを決める。候補リストは3種類しかなく、どれを使うかで、何も指定しないときのバックエンドが決まる。
- 候補リストを持たない tensor 専用のメソッドもある。Stop 中に呼ぶと、usd にフォールバックせずに AssertionError になる。
- 何も指定していない既定の状態では、フォールバックは何の通知もなく起きる。見えるようにする道具が、スパイと strict である。
- `isaacsim.core.experimental.prims.XformPrim` の姿勢のメソッドは、Play 中でも usd を読む。物理の出力先が USD でない構成では、物理で動いている剛体を XformPrim で読むと古い値が返る。

## 1. バックエンド選択の3段階

| 段階 | 判定する関数 | 判定の内容 |
|---|---|---|
| 候補からの選択 | `isaacsim.core.experimental.utils.backend.get_current_backend([候補…])` | `isaacsim.core.experimental.utils.backend.use_backend()` で指定された値があればその値、なければ候補リストの先頭を選ぶ |
| tensor の有効性の確認 | `isaacsim.core.experimental.prims.Articulation._check_for_tensor_backend()`（`isaacsim.core.experimental.prims.RigidPrim` にも同名のメソッドがある） | tensor が選ばれていても、子の view が無効なら usd に差し替える |
| 処理の分岐 | メソッド本体の `if backend == ...` | 決まったバックエンドの処理を実行する |

### 候補からの選択：isaacsim.core.experimental.utils.backend.get_current_backend

候補からの選択には、次の3つのコードが関わる。

| 役割 | コード | すること |
|---|---|---|
| 指定する | 利用者が書く `with isaacsim.core.experimental.utils.backend.use_backend("usdrt"):` | 指定値 `_context.backend` に "usdrt" を書く。ブロックを抜けるときに元の値へ戻す |
| 候補リストを渡す | ラッパーのメソッド（例：`isaacsim.core.experimental.prims.RigidPrim.get_world_poses`） | 自分が対応するバックエンドを、ソースに直接書いたリストで `get_current_backend()` に渡す |
| 読んで選ぶ | `isaacsim.core.experimental.utils.backend.get_current_backend(候補リスト)` | 指定値 `_context.backend` を読み、候補リストと照らし合わせて1つを返す |

`_context` は、`isaacsim.core.experimental.utils.impl.backend` モジュールの最上位で `threading.local()` として作られたオブジェクトである。`threading.local()` のオブジェクトは、スレッドごとに別々の値を持つ。`_context.backend` に値を書くのは `use_backend()` だけで、`get_current_backend()` は読むだけである。`get_current_backend()` が返したバックエンドは、呼び出したメソッドのローカル変数 `backend` に入るだけで、`_context` には書き戻されない。with ブロックの範囲と入れ子の扱いは [コンテキストマネージャと use_backend](../01_用語と概念/04_コンテキストマネージャとuse_backend.md) にまとめている。

以下の3つの抜粋は、どれも v6.2.0 のソースから取ったものである。読みやすくするために、docstring・型注釈・例外のメッセージの一部を省き（省いた所は `...`）、日本語のコメントを加えた。抜粋なので、このままでは実行できない。

**指定する側：use_backend。** backend.py（`isaacsim.core.experimental.utils.impl.backend`）抜粋。`_fsd_enabled` は、モジュールを読み込んだときに設定 `/app/useFabricSceneDelegate` を1回だけ読んだ値である。
```python
# backend.py（v6.2.0）抜粋：モジュールの最上位と use_backend の本体
_context = threading.local()  # スレッドごとに別々の値を持つ入れ物。use_backend の指定値をここに置く
_fsd_enabled = carb.settings.get_settings().get_as_bool("/app/useFabricSceneDelegate")  # 読み込み時に1回だけ読む


@contextlib.contextmanager
def use_backend(backend, *, raise_on_unsupported=False, raise_on_fallback=False):
    if backend in ["usdrt", "fabric"] and not _fsd_enabled:  # usdrt / fabric は Fabric Scene Delegate が有効なときだけ指定できる
        raise RuntimeError(...)
    previous_backend = getattr(_context, "backend", None)  # 外側の with で指定された値を退避する（なければ None）
    previous_raise_on_unsupported = getattr(_context, "raise_on_unsupported", False)
    previous_raise_on_fallback = getattr(_context, "raise_on_fallback", False)
    try:
        _context.backend = backend  # 指定値を書く。get_current_backend はこれを読む
        _context.raise_on_unsupported = raise_on_unsupported
        _context.raise_on_fallback = raise_on_fallback
        yield  # ここで with ブロックの中身が実行される
    finally:  # with ブロックを抜けるとき（例外で抜けるときも）
        if previous_backend is None:
            delattr(_context, "backend")  # 外側に指定がなければ、指定値を消す
        else:
            _context.backend = previous_backend  # 外側の指定値に戻す
        _context.raise_on_unsupported = previous_raise_on_unsupported
        _context.raise_on_fallback = previous_raise_on_fallback
```

**候補リストを渡す側：RigidPrim.get_world_poses と XformPrim.get_world_poses。** rigid_prim.py と xform_prim.py の抜粋。抜粋の中の `backend_utils` は `isaacsim.core.experimental.utils.backend` モジュール、`self` は `isaacsim.core.experimental.prims.RigidPrim` のインスタンスである。`isaacsim.core.experimental.prims.RigidPrim` は `isaacsim.core.experimental.prims.XformPrim` を継承しているので、`super().get_world_poses()` は `XformPrim.get_world_poses` を呼ぶ。

)
if backend == "tensor":  # 3段目：tensor なら子の view から読む
    data = self._physics_rigid_body_view.get_transforms()  # (N, 7) の配列を1回で受け取る
    ...
else:  # tensor 以外（usd / usdrt / fabric）は XformPrim の実装に任せる
    return super().get_world_poses(indices=indices)

# xform_prim.py（v6.2.0）抜粋：XformPrim.get_world_poses の本体

    ...  # USD の属性から、プリムごとに計算する
elif backend == "usdrt":
    ...  # usdrt の IFabricHierarchy から、プリムごとに読む
elif backend == "fabric":

**読んで選ぶ側：get_current_backend。** backend.py 抜粋。
```python
# backend.py（v6.2.0）抜粋：get_current_backend の本体
def get_current_backend(supported_backends, *, raise_on_unsupported=None):
    backend = getattr(_context, "backend", supported_backends[0])  # 指定値を読む。指定がなければ候補リストの先頭
    if backend not in supported_backends:  # 指定値が候補リストにない場合
        if raise_on_unsupported is None:  # 引数で決めていなければ
            raise_on_unsupported = getattr(_context, "raise_on_unsupported", False)  # use_backend のフラグに従う
        if raise_on_unsupported:
            raise RuntimeError(f"Unsupported backend: '{backend}'. Supported backends: ...")
        carb.log_warn(f"Unsupported backend: '{backend}'. Falling back to '{supported_backends[0]}' backend.")
        return supported_backends[0]  # 警告を出して、候補リストの先頭を返す
    return backend  # 指定値（または先頭）をそのまま返す
```

この関数は、view が有効かどうかを調べない。view の有効性は、次の段階の `_check_for_tensor_backend()` が調べる。

**3つを通した流れ（実測）。** 2026-11-10 にヘッドレスで、`get_current_backend` を記録用の関数に差し替えて、ケースごとに「渡された候補リスト → 返した値」と、Kit のログに出た警告を記録した（[measurements/run_selection_walkthrough.py](measurements/run_selection_walkthrough.py)、結果は同じ名前の .jsonl）。

| ケース | 状態 | use_backend の指定 | 呼んだメソッド | get_current_backend の呼び出し（候補リスト → 返した値） | 使われたバックエンド | Kit のログの警告 |
|---|---|---|---|---|---|---|
| A | Stop | なし | `RigidPrim.get_world_poses` | ① `["tensor","usd","usdrt","fabric"]` → tensor ② `["usd","usdrt","fabric"]` → usd | usd | なし |
| B | Play | なし | `RigidPrim.get_world_poses` | ① `["tensor","usd","usdrt","fabric"]` → tensor | tensor | なし |
| C | Stop | usdrt | `RigidPrim.get_world_poses` | ① → usdrt ② → usdrt | usdrt | なし |
| D | Stop | tensor | `RigidPrim.get_world_poses` | ① → tensor ② → usd | usd | 2つ（下に記す） |
| E | Play | なし | `XformPrim.get_world_poses` | ② `["usd","usdrt","fabric"]` → usd | usd | なし |
| F | Play | tensor | `XformPrim.get_world_poses` | ② → usd | usd | `Unsupported backend: 'tensor'. Falling back to 'usd' backend.` |

- A では、①で tensor が返ったが、Stop 中は子の view が無効なので `_check_for_tensor_backend()` が usd に差し替えた。指定がないので通知は出ない。usd は tensor ではないので `super().get_world_poses()` に進み、②で指定がないので候補リストの先頭 usd が返った。
- C では、指定値 usdrt が①でも②でも候補リストにあるので、そのまま返った。
- D では、①の後に `_check_for_tensor_backend()` が `Physics tensor entity is not valid for use with 'tensor' backend. Falling back to 'usd' backend.` を出して usd に差し替えた。次の②では、指定値 tensor が `["usd","usdrt","fabric"]` にないので、`get_current_backend()` が `Unsupported backend: 'tensor'. Falling back to 'usd' backend.` を出した。
- E と F は、Play 中でも `XformPrim` の候補リストに tensor がないので、usd になる。

### tensor の有効性の確認：isaacsim.core.experimental.prims.Articulation._check_for_tensor_backend

articulation.py（v6.2.0）抜粋。日本語のコメントを加えた。抜粋の中の `backend_utils` は `isaacsim.core.experimental.utils.backend` モジュール、`carb` は `carb` モジュール、`self` は `isaacsim.core.experimental.prims.Articulation` のインスタンスである。抜粋なので、このままでは実行できない。
```python
# articulation.py（v6.2.0）抜粋：Articulation._check_for_tensor_backend の本体
if backend == "tensor" and not self.is_physics_tensor_entity_valid():  # tensor が選ばれたが、子の view が無効な場合
    if backend_utils.is_backend_set():  # use_backend で何か指定されている場合だけ通知する
        if backend_utils.should_raise_on_fallback():  # raise_on_fallback が True なら
            raise RuntimeError(...)  # 例外を出す
        carb.log_warn(...)  # そうでなければ警告を出す
    return fallback_backend  # usd に差し替える（use_backend を指定していなければ、何も通知しない）
return backend  # それ以外は選ばれたバックエンドのまま返す
```

`isaacsim.core.experimental.prims.Articulation.is_physics_tensor_entity_valid()` は、「`isaacsim.core.simulation_manager.SimulationManager` の simulation view が None でない」かつ「ラッパーの子の view が None でない」ときに True を返す。子の view が無効になるのは Stop 中だけで、Pause 中は有効なままである（実測。[backend_spy](../05_観測Snippet/06_backend_spy.md)）。

## 2. 候補リストとメソッドの対応表

| `isaacsim.core.experimental.prims.Articulation`（26個） | `get_dof_positions`、`get_dof_velocities`、`set_dof_positions`、`set_dof_velocities`、`get_dof_efforts`、`set_dof_efforts`、`get_dof_projected_joint_forces`、`get_link_incoming_joint_force`、`get_velocities`、`set_velocities`、`get_jacobian_matrices`、`get_mass_matrices`、`get_dof_coriolis_and_centrifugal_compensation_forces`、`get_dof_gravity_compensation_forces`、`get_link_coms`、`set_link_coms`、`get_link_inertias`、`set_link_inertias`、`get_fixed_tendon_stiffnesses`、`get_fixed_tendon_dampings`、`get_fixed_tendon_limit_stiffnesses`、`get_fixed_tendon_limits`、`get_fixed_tendon_rest_lengths`、`get_fixed_tendon_offsets`、プロパティ `jacobian_matrix_shape`、`mass_matrix_shape` |
| `isaacsim.core.experimental.prims.RigidPrim`（7個） | `apply_forces`、`apply_forces_and_torques_at_pos`、`get_coms`、`set_coms`、`get_inertias`、`set_inertias`、プロパティ `num_shapes` |

Stop 中に呼ぶと、usd にフォールバックせずに `AssertionError: Instance's physics tensor entity is not valid. Play the simulation/timeline to re-initialize it` になる（実測）。関節角（`get_dof_positions`）は、Stop 中には読めない。Stop 中に読めるのは、候補リストに usd を持つ `get_dof_position_targets` などの設定値である。

### docstring のタグを読むときの注意

`isaacsim.core.experimental.prims.Articulation` には、docstring に「Backends: usd, tensor」と書かれた項目が多数ある。これらの中には、`isaacsim.core.experimental.prims.Articulation.num_dofs` や `isaacsim.core.experimental.prims.Articulation.dof_names` などのプロパティがあり、`isaacsim.core.experimental.utils.backend.get_current_backend()` を経由しない。逆に、docstring に「Backends: tensor」とだけ書かれたメソッドは、上の tensor 専用のメソッドである。バックエンドの選ばれ方は、タグではなく、メソッド本体の `isaacsim.core.experimental.utils.backend.get_current_backend()` の呼び出しで確かめる。

## 3. フォールバックの通知のされ方

| 状況                                                                                                    | 通知                                   |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `isaacsim.core.experimental.utils.backend.use_backend()` を使っていない状態で、tensor の子の view が無効なため usd に差し替わる | 何も出ない                                |
| `isaacsim.core.experimental.utils.backend.use_backend()` で指定したが、その時点では使えないため差し替わる                     | `carb.log_warn` で警告が出る               |
| `isaacsim.core.experimental.utils.backend.use_backend()` で、そのメソッドが対応していないバックエンドを指定した                  | `carb.log_warn` で警告が出て、候補リストの先頭が使われる |
| 上の2つで、raise_on_fallback（使えない場合）または raise_on_unsupported（非対応の場合）が True                                 | RuntimeError が出る                     |

`carb.log_warn` の警告は、Kit のログに出る。出力先は、Console ウィンドウ、ログファイル（`/log/file` の場所）、端末（`/log/outputStreamLevel` が Warning 以下なら）である。Script Editor のログ欄には出ない。Script Editor のログ欄は、実行したコードの標準出力と標準エラーのイベントだけを表示するからである（`omni.kit.window.script_editor` の `log_view.py` の `LogModel` が受け取るのは、`GLOBAL_EVENT_SCRIPT_STDOUT_IMMEDIATE` などの3種類のイベントだけ）。Python の `sys.stdout` も通らない（実測：`contextlib.redirect_stdout` で受け取ると、print の文字列だけが入り、`carb.log_warn` の文字列は入らなかった）。

### 既定の状態でも検知する道具

| 道具 | 向いている用途 | Snippet |
|---|---|---|
| スパイ | 多くのメソッドを一度に調べて、全件をログに残す | [backend_spy](../05_観測Snippet/06_backend_spy.md) |
| strict | 1つの仮説を、外れたら例外で即座に知る | [strict_backend](../05_観測Snippet/07_strict_backend.md) |

### スパイが成り立つ理由

- ラッパーのメソッドは、`isaacsim.core.experimental.utils.backend` モジュールの属性 `get_current_backend` を、呼び出すたびにモジュールから取り出して呼んでいる。そのため、モジュールの属性 `get_current_backend` を別の関数に差し替えれば、すべての呼び出しを横取りできる。
- 公開されている `isaacsim.core.experimental.utils.backend` モジュールの中身は、`from .impl.backend import *` の1行だけである。`isaacsim.core.experimental.utils.impl.backend._context` のようにアンダースコアで始まる名前は `import *` では取り込まれない。そのため、指定値を読むときは `isaacsim.core.experimental.utils.impl.backend` から読む。
- tensor 専用のメソッドとプロパティは `get_current_backend` を呼ばないので、スパイに映らない。

## 4. strict による仮説検証

strict は、`isaacsim.core.experimental.utils.backend.use_backend()` の2つのフラグ（raise_on_unsupported と raise_on_fallback）を True に固定したものである。「この範囲の呼び出しは、すべて指定したバックエンドで処理される」という仮説を書くための記法として使う。仮説が外れると、例外で即座に分かる。

strict_backend.py 抜粋（全体は [snippets/strict_backend.py](../snippets/strict_backend.py)）
```python
# strict_backend.py 抜粋：2つの raise フラグを True に固定した use_backend を作る
import functools  # 引数を固定した関数を作るために使う
import isaacsim.core.experimental.utils.backend as backend_utils  # use_backend を提供するモジュール

strict = functools.partial(backend_utils.use_backend, raise_on_unsupported=True, raise_on_fallback=True)  # 指定どおりに処理されなければ例外にする use_backend
```

2つのフラグの既定値を True に変える設定項目はない。6.2.0 でフラグを設定する手段は、`isaacsim.core.experimental.utils.backend.use_backend()` の引数だけである。

### 使い方

- 仮説の範囲だけを `with strict("tensor"):` で囲む。すべてのコードを strict で囲むわけではない。
- 範囲の中でバックエンドが混ざる処理は、区間ごとに `with` を分ける。
- with ブロックの中で登録したコールバックには効かない。ブロックを抜けた後の更新で呼ばれたコールバックの中では、指定は外れている（実測：with の中で登録した物理ステップのコールバックの中で読むと、指定値は None で、tensor が選ばれた）。ただし、with の中で `isaacsim.core.simulation_manager.SimulationManager.step()` を呼んだ場合は、そのステップのコールバックが with の中で同じスレッドから呼ばれるので、指定が効く（実測）。コールバックの中で効かせたい場合は、コールバックの中に `with strict(...)` を書く（[コンテキストマネージャとuse_backend](../01_用語と概念/04_コンテキストマネージャとuse_backend.md)）。

### 例外の読み方と、状態ごとの結果

| 例外のメッセージ | 意味 | 外れた仮説 |
|---|---|---|
| `Unsupported backend: 'tensor'. Supported backends: 'usd', 'usdrt', 'fabric'` | そのメソッドは、指定したバックエンドに対応していない | 「このメソッドは〇〇で処理できる」 |
| `Physics tensor entity is not valid. Fallback set to 'usd' backend.` | 対応はしているが、子の view が無効だった | 「今の状態では tensor が使える」 |

| 呼び出し | Stop | Play | Pause |
|---|---|---|---|
| `with strict("tensor"): XformPrim.get_world_poses()` | Unsupported backend | Unsupported backend | Unsupported backend |
| `with strict("tensor"): RigidPrim.get_world_poses()` | Physics tensor entity is not valid | 成功 | 成功 |

（2026-11-09 にヘッドレスで実測。[strict_backend](../05_観測Snippet/07_strict_backend.md)）

フラグは、`isaacsim.core.experimental.utils.backend.use_backend()`（strict を含む）で何かを指定したときにだけ効く。何も指定していなければ、例外は出ず、フォールバックは何の通知もなく起きる。

## 5. Play 中に XformPrim が読む値と、物理の出力先

`isaacsim.core.experimental.prims.XformPrim` の姿勢・スケールの7メソッドは、候補リストが usd から始まるので、Play 中でも、何も指定しなければ usd を読む。usd の経路は `pxr.UsdGeom.Xformable(prim).ComputeLocalToWorldTransform()` を呼ぶだけで、`/physics/updateToUsd` の値を確認しない（ソース）。そのため、物理で動いている剛体を XformPrim で読むと、USD に最後に書かれた値が返る。

### 物理の出力先の設定

| 出力先 | 設定の値 | 切り替えるコード |
|---|---|---|
| USD へ書く（GUI の既定） | `/physics/updateToUsd`・`/physics/updateVelocitiesToUsd`・`/physics/updateParticlesToUsd`・`/physics/updateForceSensorsToUsd` が true、omni.physx.fabric 拡張は無効 | `isaacsim.core.simulation_manager.SimulationManager.enable_fabric(False)` |
| Fabric へ書く | 4つが false、omni.physx.fabric 拡張は有効 | `isaacsim.core.simulation_manager.SimulationManager.enable_fabric(True)` |
| どちらにも書かない | 4つが false、omni.physx.fabric 拡張は無効 | `enable_fabric(False)` の後に、4つの設定を false にする |

`isaac-sim.bat` が使う `isaacsim.exp.full.kit` は、omni.physx.fabric を依存に明記していない。実行時の状態を GUI で確かめると、omni.physx.fabric は無効、`/physics/updateToUsd` は true だった（[env_fingerprint](../05_観測Snippet/01_env_fingerprint.md) の結果）。Isaac Lab は、Fabric を使う既定の構成で、omni.physx.fabric を有効にし、USD への書き戻しを OFF にする[^lab]。

### 出力先ごとに、どの経路が物理の最新値を返すか（実測）

落下する剛体の高さを4つの経路で読み比べた結果である（2026-11-09、[pose_freshness_probe](../05_観測Snippet/05_pose_freshness_probe.md)）。「変わる」は、Play 中に物理の最新値と同じ値が更新ごとに出たことを表す。

| 物理の出力先 | XformPrim 既定（usd） | XformPrim usdrt | XformPrim fabric | RigidPrim 既定（tensor） |
|---|---|---|---|---|
| USD へ書く（既定） | 変わる | 変わる | 変わる | 変わる |
| どちらにも書かない | 変わらない（Play 前の値） | 変わらない | 変わらない | 変わる |
| Fabric へ書く | 変わらない（Play 前の値） | 変わる | 変わる | 変わる |

USD へ書く既定の構成では、USD に書かれた値が Fabric にも写されるので、usdrt / fabric でも最新の値が読める。usd・usdrt・fabric の経路は、Stop・Play・Pause のどの状態でも例外にならなかった。

### 物理で動く物体を読むときの選び方

| 読みたいもの | 使うラッパー | Play 中に選ばれるバックエンド |
|---|---|---|
| 剛体の姿勢 | `isaacsim.core.experimental.prims.RigidPrim` | tensor（物理エンジンの最新値。出力先に関係ない） |
| `isaacsim.core.experimental.prims.Articulation` のルートの姿勢 | `isaacsim.core.experimental.prims.Articulation` | tensor（物理エンジンの最新値） |
| 物理を持たない Xform の姿勢 | `isaacsim.core.experimental.prims.XformPrim` | usd（Fabric を読みたい場合は `isaacsim.core.experimental.utils.backend.use_backend()` で指定する） |

`isaacsim.core.experimental.prims.XformPrim` の既定が usd になっている理由は、公式の文書・docstring・CHANGELOG のどれにも書かれていない。ソースから分かる事実は、usd の経路は Fabric Scene Delegate の有無にかかわらず使えること、usdrt と fabric は Fabric Scene Delegate が無効だと `isaacsim.core.experimental.utils.backend.use_backend()` が RuntimeError を出すこと、の2つである。Fabric Scene Delegate の設定（`/app/useFabricSceneDelegate`）は、`isaacsim.core.experimental.utils.backend` モジュールが読み込まれたときに1回だけ読まれ、起動後に変えても判定は変わらない（ソースと実測：起動後に false にしても `use_backend("usdrt")` は例外にならなかった）。

## 6. simstate

6.2.0 で加わった `/isaacsim/articulation/simStateMode` の設定は、次の3メソッドだけが参照する。

- `isaacsim.core.experimental.prims.Articulation.set_dof_position_targets`
- `isaacsim.core.experimental.prims.Articulation.set_dof_velocity_targets`
- `isaacsim.core.experimental.prims.Articulation.set_dof_efforts`

| 値 | 意味（ソース） | このインストールでの実測 |
|---|---|---|
| disabled | 設定がない場合の値。simstate を使わない | 通常のバックエンドに書かれた |
| mirror | 通常のバックエンドと simstate の両方に書く | 通常のバックエンドには書かれた。simstate への書き込みは失敗し、エラーのログが出た |
| exclusive | simstate だけに書く。`isaacsim.core.experimental.utils.backend.use_backend("simstate")` を指定した範囲も、この扱いになる | どこにも書かれなかった（目標値が前の値のまま変わらなかった）。エラーのログが出た |

simstate の書き込み先は、`isaacsim.mega.sim_state.client` モジュールの SimStateStorage である。ラッパーは、DOF ごとのジョイントのパスとプロパティ名（`drive:angular:physics:targetPosition` など。角度は度に直す）の組で値を渡す（`articulation.py` の `_write_dof_data_to_simstate`）。このモジュールは Isaac Sim 6.2.0 のインストールに含まれていない。そのため、mirror と exclusive では `Failed to create SimStateStorage: No module named 'isaacsim.mega'` というエラーのログが出て、simstate への書き込みは行われない（2026-11-09 にヘッドレスで実測）。exclusive は通常のバックエンドへの書き込みも飛ばすので、関節の目標値が反映されなくなる。

## このノートに出てくる API の import

このノートでは、関数とクラスを `モジュール名.クラス名.メソッド名` の完全修飾名で書いている。Script Editor で使うときは、次の import を先に実行する。import した後は、完全修飾名からモジュール名の部分を除いた名前で呼べる。たとえば `isaacsim.core.simulation_manager.SimulationManager.enable_fabric()` は `SimulationManager.enable_fabric()`、`isaacsim.core.experimental.utils.backend.use_backend()` は `backend_utils.use_backend()` と書く。

# このノートに出てくる API の import
